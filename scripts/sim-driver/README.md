# Simulator driver

Moved verbatim from `AGENTS.md` on 2026-11-02; `AGENTS.md` points here. Keep it current when a `sim` command changes.

Check the shell on a simulator with no person through `scripts/sim-driver/sim` (`sim help` lists the commands): it builds and installs the shell from the working tree (or `--from REV`) in a staged copy under `~/Library/Caches/my-love-sim-driver/<checkout>-<hash>`, one per checkout (`SIM_DRIVER_WORK` overrides it), never the repo's `dist/` or `ios/App/App/public/`, against the local stack, uninstalling the old shell first; serves the working tree as a live update (`serve-update`, stopped with `--stop`); folds, rotates, taps, scrolls, dumps the web view's elements as JSON and reads story 7's readout as text through `ax` and an XCUITest runner it builds outside `ios/App`; and answers the notification permission alert, pushes, and reads banners (tapping one from a cold or backgrounded app, or with `banner FILE --front` watching for one while the shell is in front, which ends in `no banner` when the shell shows none), Notification Center's groups (`center` unfolds the Duo to portrait to read, proven with 8 groups, and puts the pose and orientation back, but a landscape start that is not unfolded (a folded Duo, or a phone with no pose) only when the shell, the host app, Settings or Safari was in front; it ends on the Home Screen, except that such a start gets that app back) and the icon badge (`permission`, `push`, `banner`, `center`, `badge`) for the shell or, with `--host`, the runner's own host app, which asks for permission itself, so these steps are checked without any push code in the shell. `sim pending [BUNDLE|--host]` prints an app's scheduled local notifications as one JSON line decoded from the simulator's own `UserNotifications` files (a record it does not recognise exits 1 and prints nothing; iOS writes the file some time after a schedule, after a fresh install's first one sometimes not until the app's next launch, so an empty or stale list read right after one is not proof), `sim schedule FILE` and `sim unschedule ID…` have the host app schedule or remove requests (`scripts/sim-driver/fixtures/host-requests.json` is the known-good schedule; `schedule` needs `sim permission allow --host` first) and return once `pending --host` shows the change — both launch the host, which leaves it in front of the shell, and `sim permission reset --host` uninstalls the host, wiping its pending requests — and `zsh scripts/sim-driver/test-pending.zsh` checks the decoder with no simulator. `sim watch [--front] [--for SECONDS]` waits for the app's banner with nothing pushed, such as a scheduled notification falling due (start it a minute or more before the due time), and `sim reboot` restarts the simulator, which ignores a Mac clock change until it reboots, so run it after each `sudo /bin/date` before expecting a scheduled notification to fire. A run needs `ax` and `xcodegen` installed with every `ax doctor` line ok, the Mac unlocked, Device Hub open, not minimised and on the current Space or assigned to All Desktops (it need not be in front), and `supabase start`. Run one Duo story at a time, or each in its own worktree on its own `xcrun simctl clone` with its own `serve-update` port and its own Device Hub window: `ax`, and so every `sim` step that folds, rotates, presses Home or reads state, drives the device `--device` names through the window that shows it, whichever window is in front, and refuses one no window shows ("No Device Hub window shows …", exit 4), so those `sim` steps first select the device in a window that shows no other booted simulator, opening one with File > New Window when every window shows one; a worktree's folder there is not removed with it and can be deleted once the worktree is gone. Trust simulator results for the shell only: story 7 found the simulator's Safari and Home Screen web app differ from the Duo. Its three fixture pairs, local stack only and made by `sim provision`, are the driver's: `simdriver@test.example.com` and `simdriver-partner@test.example.com`, seeded so every view scrolls, `simdriver-other@test.example.com` and `simdriver-other-partner@test.example.com`, linked with no seeded rows, for a sign-out and sign-in as another couple (`sim signin other|other-partner`, `sim signout`), and `simdriver-unlinked@test.example.com` (Riley) and `simdriver-unlinked-other@test.example.com` (Quinn), unlinked with every partner request involving either deleted on each provision, for partner-request checks (`sim signin unlinked|unlinked-other`); no E2E slot or other tool uses them. `sim signin --decline-push` answers the notification alert Don't Allow, since the runner otherwise answers Allow on its first touch after sign-in (use it after `sim permission reset`). `sim dates kinds|many|clear` sets, for Casey and Jessie only, the dates the date reminders are planned from (one of each kind, or 70 reminders' worth); `kinds` and `many` first do what `clear` does — delete both people's events, anniversaries and countdown marks and the pair's couple settings, null both birthdays and turn both people's date reminders back on — and their event and birthday writes send the other person date-change pushes; `sim provision` restores only the seeded events, so run `sim dates clear` and then `sim provision` to get back the provisioned state.
